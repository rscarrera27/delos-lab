# Delos Lab 문서

이 디렉터리는 구현을 처음 실행하는 사람, 프로토콜을 공부하는 사람, 코드를 변경하는
사람이 같은 용어와 경계를 공유하도록 구성돼 있다. Delos 논문 자체의 대체 설명서가
아니며, 코드가 주장하는 범위와 주장하지 않는 범위를 명시하는 것이 목적이다.

## 권장 읽기 순서

1. 루트 [README](../README.md)에서 설치하고 첫 재구성 실험을 실행한다.
2. [개념 지도](learning-guide.md)에서 VirtualLog, Loglet, MetaStore, NativeLoglet과
   Paxos proposer의 역할을 구분한다.
3. [코드 워크스루](code-walkthrough.md)를 따라 계약에서 PUT·GET·재구성·새 DB 편입까지
   실제 호출 경로를 읽는다.
4. [아키텍처](architecture.md)에서 패키지 소유권과 런타임 프로세스 배치를 확인한다.
5. [논문-구현 대조표](paper-implementation-map.md)에서 구현, 축소 구현과 제외 범위를
   확인한다.
6. [테스트 학습 지도](test-scenarios.md)를 따라 전제·사건·보장 단위로 테스트를 읽는다.
7. [형식 모델](../formal/README.md)의 유한 상태 모델이 검사하는 불변식과 한계를 확인한다.

## 문서별 책임

| 문서 | 답하는 질문 |
|---|---|
| [개념 지도](learning-guide.md) | 용어가 무엇이며 요청과 재구성은 어떤 순서로 진행되는가? |
| [코드 워크스루](code-walkthrough.md) | 어느 파일부터 읽고 실제 호출을 어떻게 끝까지 추적하는가? |
| [아키텍처](architecture.md) | 어느 패키지가 어떤 계약을 소유하고 무엇에 의존할 수 있는가? |
| [논문-구현 대조표](paper-implementation-map.md) | 논문과 같거나 다른 부분은 무엇인가? |
| [테스트 학습 지도](test-scenarios.md) | 각 테스트는 어떤 분산시스템 보장을 확인하는가? |
| [설계 결정](design-decisions.md) | Docker, 일반화된 장애주입 등을 사용하지 않은 이유는 무엇인가? |
| [공개 체크리스트](release-checklist.md) | 공개 또는 릴리스 직전에 무엇을 다시 검증해야 하는가? |

코드와 문서가 충돌하면 테스트와 공개 인터페이스를 먼저 확인하고 문서를 함께 수정한다.
테스트 개수처럼 자주 바뀌는 숫자보다는 계약 이름과 실행 명령을 문서화한다.
